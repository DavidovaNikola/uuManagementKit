Manažerské shrnutí

V rámci 4. milníku bylo provedeno 7 testovacích scénářů pokrývajících klíčové funkční oblasti aplikace uuManagementKit — správu dokumentů (DOC), tvorbu a úpravu schůzek (CRT, UPD) a vytváření požadavků (REQ). Testování probíhalo v období 14.–22. 4. 2026 podle definované Test Strategy v rámci vodopádového modelu.

Výsledkem je 10 nalezených defektů, z nichž 3 mají kritickou závažnost a brání plné akceptaci produktu. Nejzávažnější nálezy se týkají modulu Create Request (BE chyba 400 Bad Request, prázdná chybová hláška) a modulu Create document (možnost vytvořit dokument s pouze whitespace názvem, který následně nelze otevřít).

Modul Set document state (TC-DOC-03) prošel bez nálezu včetně zátěžového testu (5000 znaků v komentáři). Funkce Copy document a Update document jsou rovněž stabilní; u Update document byla zaznamenána pouze UX nekonzistence (dvojklik vs. kebab menu), která nebrání akceptaci.

⚠ Doporučení: Sign-off podmíněně po opravě 3 critical bugů

Blocker · TC-REQ-01
Backend chyba 400 Bad Request / artifactLoadFailed — request nelze vytvořit. Nutná oprava před release.
Blocker · TC-DOC-01
Dokument lze vytvořit s názvem o samé mezery; následně jej nelze otevřít. Vstupní validace chybí.
Blocker · TC-UPD-02
Datum ukončení může být dřívější než datum zahájení — chybí business validace, dochází k tichému přepisu dat.
UX · 4× Major
Nespecifické / prázdné chybové hlášky napříč moduly — uživatel nedostává srozumitelnou zpětnou vazbu.
Pozitivum
Modul Set document state (6 sub-scénářů včetně zátěžového) — všechny PASS bez výhrad.

Doporučení k akceptaci

1. Před Sign-off opravit Critical (A) chyby: 3 nálezy v modulech Create Request, Create document a Update meeting blokují plnou akceptaci dle kritéria definovaného v Test Strategy (Fáze 4: „Všechny chyby s prioritou Vysoká a Kritická jsou vyřešeny a ověřeny").

2. Major (B) chyby — UX hlášky: 5 nálezů týkajících se nesrozumitelných nebo prázdných validačních hlášek doporučujeme zařadit do nejbližšího patche po Sign-off. Nepředstavují funkční blocker, ale degradují uživatelský zážitek.

3. Minor (C) chyby: 2 nálezy nízké závažnosti lze řešit v rámci běžné údržby.

4. Re-testing scope: po opravách doporučujeme regresní průchod TC-DOC-01, TC-REQ-01, TC-UPD-02 a smoke check zbývajících scénářů. Odhadovaná pracnost: ~2 hodiny QA.

5. Návrh na rozšíření test setu: doplnit explicitní edge-case scénáře pro vstupní validaci textových polí (whitespace, neviditelné znaky, prázdné hodnoty) napříč všemi formuláři aplikace.
